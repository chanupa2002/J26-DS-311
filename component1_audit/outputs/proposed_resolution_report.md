Maintain a versioned crosswalk of disposition counts only; preserve the observed master as delivered until verified. If the 6,850 is a different denominator, document the definition and source.

### 2. Consumption derivation and bottom-quintile proxy

- **Source and variables:** J1 cleaned food items: `mod_j1_food_consumption` (including `j1_01`, `j1_08`); K non-food item-period export: exact amount and period columns in `mod_k_non_food_expenditure`; candidate-map source families `j1 long`, `k long`, `k wide`, `b0`. - **Questionnaire:** J1 item consumption/value refers to the past 7 days (PDF pp.157–158). K asks non-food expenditure by recall period (PDF pp.173–176); questionnaire establishes that periods differ, but the period-code conversion table and operational rules are not present in an accompanying codebook. J1 has consumed/not-consumed responses and value; exact cleaned recode crosswalk to questionnaire codes must be recovered.
- **Observed/current implementation:** prepared `pc_cons` equals `total_month / hh_size` for all 6,847 rows. `label_high_vuln` equals the weighted bottom-quintile classification of prepared `pc_cons` (weighted prevalence 0.200085; observed threshold ≈15,858.47). This only establishes downstream relationships. It does not reveal how monthly household total was built. J1 has 255,605 consumed item rows, of which 65,573 have blank `j1_08`; non-consumed rows are blank by design in the cleaned data. K has 472,443 item-period rows, 36,286 blank amounts and 257,691 recorded zeros. `n_food_unvalued>0` for 858 prepared households (maximum 4 components). The source-to-feature code is unavailable.
- **Unreproducible steps:** exact included item list; food quantity/value rule; missing consumed-item treatment; J1 week-to-month factor; K period codes and conversion factors; treatment of blank vs explicit zero; whether and how any other food/non-food modules enter; unit/price normalization; equivalence scale formula; `pc_cons_w` definition; household weight selection; weighted quantile algorithm and tie handling; and the route from source to `total_month` and `n_food_unvalued`.
- **Recommended resolution:** reconstruct a new, versioned consumption pipeline from source rows, instrument universe, and approved period/code map. Preserve value, missingness, applicability, and imputation/audit flags as separate fields. No unknown-to-zero conversion. Produce alternative totals for unresolved missingness/period rules as sensitivity outputs, not silently selected values. Keep the bottom-quintile field only as an explicitly relative, within-sample exploratory proxy; never official eligibility or independent ground truth.
- **Affected:** 65,573 consumed J1 rows with missing value; 36,286 K rows with missing amount; 858 households flagged by existing `n_food_unvalued`; full 6,847 label population. These overlap and must not be summed as unique households.
- **Verification:** item-level code/skip domain tests; period conversion examples checked against questionnaire; unit tests for each period factor and 7-day conversion; independently aggregate J1 and K by `hhcode`; preserve all 6,847 spine rows; hand-check selected arithmetic without publishing IDs; compare totals to prepared outputs and explain every difference; test weighted quintile and tie behavior explicitly.
- **Approval:** **Yes**, for included components, periods/conversions, missing-value policy, equivalence scale, weights, and proxy interpretation.

Do not recode cleaned 0/1, sum debt amounts, count debt sources, aggregate repayment categories, calculate debt ratios or combine savings forms. - **Remaining approval/evidence:** obtain the source transformation/code crosswalk for questionnaire 1/2 to cleaned 0/1; resolve the 11 all-blank debt-positive records and amount-slot logic; define debt/income periods and zero-income handling only after source amounts are reconstructed; establish the N2/N3 respondent universe before comparing forms.

## Cross-cutting implementation and acceptance plan

1. **Freeze inputs without editing them.** Record file names, sizes, hashes, survey/instrument version, extraction date, and R/package versions in a versioned manifest. Pin the 6,847-household master key set by hash in restricted local storage; do not put identifiers in public reports.
2. **Create an approved item-level crosswalk.** Include exact file/column, questionnaire item ID and wording, response labels/codes, universe and skip gates, reference period/unit, grain/key, missing/unknown/refused/inapplicable meanings, household aggregation, expected direction, provenance, and approval status. Preserve original cleaned values and represent recoding as a derived field with explicit mapping.
3. **Build independent aggregates.** Start with the declared household spine. Aggregate each person/job/item/loan/crop/event source independently to one row per `hhcode`, preserving all-missing as missing and retaining valid-count/applicability fields. Assert uniqueness before each join and invariant household row count/key set after each join. No raw long-to-long joins.
4. **Keep alternative treatments auditable.** Until choices are approved, write versioned candidate outputs to a new resolution run directory, with rule ID, input hashes, row counts, exclusions (expected zero unless explicitly approved), missingness and delta-to-current summaries. Do not overwrite prepared outputs.
5. **Automated acceptance tests.** (a) master and prepared key uniqueness, key-set reconciliation, expected 6,847 rows; (b) source code domains and missingness baselines; (c) no unapproved recoding of 997/998/999; (d) FIES item scoring and respondent/partial rules; (e) household income deduplication/no summation; (f) debt all-NA vs explicit zero and ratio denominator cases; (g) roster/member key and age checks; (h) applicable versus structural skip counts; (i) independently aggregated synthetic and real long-table joins prove one-to-one and preserve 6,847 rows; (j) consumption period arithmetic and bottom-quintile tie/weight behavior; (k) output manifest plus deterministic rerun comparison. Existing `R/02_tests.R` covers baseline row/missingness/key/code and synthetic join assertions, but needs additional production checks above.
6. **Review gate.** Do not approve D1–D7 indicators or fit fuzzy/Bayesian methods until the researcher signs the variable crosswalk, household universe, missingness rules, consumption reconstruction, FIES rule, income/debt/savings semantics, and season/applicability decisions. The bottom-quintile proxy stays exploratory and non-independent.
